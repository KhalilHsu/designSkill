# Layout Composition

Read this to choose page structure, section order, and grid behavior. Do not treat these modes as fixed templates; choose based on the user's task, content, and data shape.

Output after reading:

- Page structure.
- First-screen composition.
- Section order or app shell regions.
- Desktop grid behavior.
- Mobile reflow behavior.

## Page Rhythm

A strong page has a readable rhythm:

- Opening: orient the user quickly.
- Proof or preview: show what exists or why it matters.
- Explanation: break the product, concept, or content into scannable sections.
- Detail: provide features, examples, data, or comparisons.
- Close: end with a decisive action or next step.

This is not limited to marketing pages. App screens also need orientation, primary task area, supporting context, and secondary actions.

## Composition Modes

Use composition modes intentionally:

- Centered stack: best for strong statements, focused onboarding, compact hero sections.
- Split layout: best for pairing copy with screenshot, media, form, or live preview.
- Contained grid: best for features, cards, tools, resources, or repeated content.
- Full-bleed band: best for mood shifts, product showcases, major transitions.
- Sidebar/app shell: best for persistent navigation and workflows.
- Dense table/card hybrid: best for management, analytics, operations, and data products.
- Master-detail: best for generated pages that need a selected record plus related records, actions, or context.

## Container Width

Match max-width to content:

- 720-860px: focused text and editorial pages.
- 960-1120px: product pages and compact marketing pages.
- 1200-1440px: SaaS, dashboards, docs, data-heavy pages.
- Full viewport: immersive hero, background effects, app shells.

Wide layouts still need internal alignment and line-length control.

## Section Spacing

Use a consistent section gap:

- Compact app UI: 16-32px.
- Standard web page: 48-80px.
- Spacious product/editorial page: 96-160px.

Section spacing should respond on mobile. Large desktop gaps often need to shrink.

## Grids

Choose grid count by content, not symmetry alone:

- 2 columns: explanation plus media.
- 3 columns: feature sets, cards, benefits.
- 4 columns: compact categories, logos, product listings.
- 12-column grid: complex pages requiring flexible spans.

Cards should not all have equal visual weight if the content has different importance.

## Navigation

Navigation should match page complexity:

- Minimal top nav for simple pages.
- Sticky nav for long pages or product sites.
- Sidebar for app workflows or documentation.
- Local tabs for content filtering.
- Announcement banner only when it has clear value.

Keep primary action visually distinct from normal navigation.

## Hero Sections

A hero needs:

- Clear headline.
- Supporting line or evidence.
- Primary action or next step when appropriate.
- Visual anchor: product image, abstract system, gradient, code panel, data view, or strong typography.

Avoid hero sections that are only a centered headline and generic button unless the typography and atmosphere are strong enough to carry the page.

For data-backed pages, the first screen may be a record masthead, score summary, dashboard header, or primary work area instead of a marketing hero.

## Content Blocks

Common blocks:

- Feature grid.
- Product screenshot panel.
- Testimonial or proof row.
- Comparison table.
- Pricing/cards.
- FAQ/details.
- Form/search/filter.
- Data summary.
- Timeline/process.
- Callout or announcement.

Use only blocks that serve the requested page.
